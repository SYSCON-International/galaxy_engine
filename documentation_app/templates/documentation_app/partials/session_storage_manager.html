Session Storage Manager

File: GalaxySessionStorageManager.js
Tag: N/A
Extends: N/A
Serializes calls that persist session-like state so that a write in progress is never aborted to make room for a newer call, and a newer call is never merged with, or discarded in favor of, another one. Every call to set() is queued and processed strictly in the order it was received, one at a time. This class only owns the queueing/ordering guarantee -- it does not implement any network transport or storage itself. The consumer supplies a persist function at construction time (e.g. an AJAX call to a Django endpoint), so the same queue can back any storage/endpoint implementation.

Attributes

None

This is a plain JS class, not a custom element -- it has no attributes. Its behavior is configured entirely through the constructor.

Methods

constructor(persist)

persist is called with a shallow clone of the variables passed to set(), and must return a Promise (or thenable, e.g. a jQuery jqXHR) that resolves when the write has completed and rejects if it fails.

set(variables)

Queues a write of variables. Every accepted call is executed in the order it was received -- a write already in progress is never aborted to start this one, and this one is never dropped or coalesced with another queued call. variables is shallow-cloned immediately (before this call returns), not when the write actually runs, so a caller that mutates the object it passed in afterward cannot affect a write still waiting in the queue. Returns a Promise that resolves or rejects with the outcome of this specific write once it actually runs -- not merely once it is queued.

Getters / Setters

pending_count

get: The number of writes still waiting to start. Does not include the currently active write, if any.

is_active

get: True if a write is currently in flight.

has_pending

get: True if a write is queued or currently in flight (is_active || pending_count > 0). Intended for callers that want to guard against leaving the page (e.g. a beforeunload handler that shows the browser's native confirmation) while a write has not yet completed -- see the Example below. Note that this only blocks navigation; it doesn't, by itself, let an in-flight write survive a navigation the user confirms anyway -- that requires the persist transport itself to be built on something that keeps running after unload, such as fetch(url, {keepalive: true}) or navigator.sendBeacon.

Observers

None

This class has no attributes, so there are no attribute observers.

Example


            let session_storage_manager = new GalaxySessionStorageManager((variables) => {
                return $.ajax({
                    url: set_session_variables_url,
                    type: "POST",
                    data: {csrfmiddlewaretoken: CSRF_TOKEN, session_variables_dictionary: JSON.stringify(variables)}
                });
            });

            // Rapid calls are queued FIFO -- B doesn't start until A's write has actually resolved.
            session_storage_manager.set({foo: 1});
            let second_write = session_storage_manager.set({bar: 2});

            await second_write; // resolves once B has actually run, not merely once it was queued

            // Guard against navigating away mid-write
            window.addEventListener("beforeunload", (event) => {
                if (session_storage_manager.has_pending) {
                    event.preventDefault();
                    event.returnValue = ""; // required for the browser's native confirmation dialog
                }
            });
