Datetime Range

File: GalaxyDatetimeRangePickerBase.js
Tag: galaxy-datetime-range
Extends: GalaxyInputBase
A datetime range picker: a preset-range select (All, Today, This Week, This Month, Custom) and, only when Custom is selected, a pair of start/end Datetime Picker fields. Note: despite the "Base" in its class name, this is the actual registered, consumer-facing element -- there is no separate leaf subclass, unlike Date Picker/ Time Picker/Datetime Picker, which each have a thin subclass of their own base.

Attributes

custom-range

Observed: false -- toggled imperatively, not reactive
Default: false
Present when the preset select is set to Custom; shows the start/end datetime fields via CSS. Toggled automatically by toggle_datetime_pickers() -- setting it directly does not change the select's own value.

Methods

set_event_listeners()

Wires the preset select's change event to toggle_datetime_pickers().

toggle_datetime_pickers()

Sets or removes the custom-range attribute based on whether the preset select is currently set to Custom.

async on_create()

Builds the preset select and a start/end pair of Datetime Picker elements, inserts them after the label row, and wires listeners. See also GalaxyHTMLComponentBase.

Getters / Setters

value

get: Returns {start, end, range}, where range is the preset select's current value, and start/end are each the corresponding picker's value_dictionary (or null) when range is "Custom", and null/null otherwise.
set: Applies {range, start, end} -- range selects the preset (falling back to "All" if unrecognized) and toggles the custom-range attribute; start/end (an ISO string or {year, month, day, hour, minute} object each) are applied to the nested pickers when present.

Observers

None

observed_attributes returns [] -- nothing here is attribute-reactive. range_change/range_valid (below) are plain custom events, not attribute observers.

on_range_change()

Fires whenever anything that affects the current range changes -- the preset select, or either nested picker's value (bound to both's input_validated event, which Datetime Picker Base dispatches on every value change, not just invalid ones). Dispatches the debounced range_change event, and range_valid if is_range_valid().

is_range_valid()

Whether the current selection is complete and well-formed. A preset range ("All", "Today", etc.) is always valid on its own; "Custom" additionally requires both the start and end pickers to hold a well-formatted, non-empty value.

Example


            
        

            let report_range = document.querySelector('#report_range');

            report_range.addEventListener('range_change', (event) => console.log('range changed:', event.detail));
            report_range.addEventListener('range_valid', (event) => console.log('range is complete:', event.detail));

            report_range.value = {
                range: "Custom",
                start: {year: 2026, month: 1, day: 1, hour: 0, minute: 0},
                end: {year: 2026, month: 1, day: 31, hour: 23, minute: 59}
            };

            console.log(report_range.value); // {start, end, range}
