Datetime Range

File: GalaxyDatetimeRangePickerBase.js
Tag: galaxy-datetime-range
Extends: GalaxyInputBase
A datetime range picker: a preset-range select (All, Today, This Week, This Month, Custom) and, only when Custom is selected, a pair of start/end Datetime Picker fields. Note: despite the "Base" in its class name, this is the actual registered, consumer-facing element -- there is no separate leaf subclass, unlike Date Picker/ Time Picker/Datetime Picker, which each have a thin subclass of their own base.

Attributes

custom-range

Observed: false -- toggled imperatively, not reactive
Default: false
Present when the preset select is set to Custom; shows the start/end datetime fields via CSS. Toggled automatically by toggle_datetime_pickers() -- setting it directly does not change the select's own value.

Methods

set_event_listeners()

Wires the preset select's change event to toggle_datetime_pickers().

toggle_datetime_pickers()

Sets or removes the custom-range attribute based on whether the preset select is currently set to Custom.

async on_create()

Builds the preset select and a start/end pair of Datetime Picker elements, inserts them after the label row, and wires listeners. See also GalaxyHTMLComponentBase.

Getters / Setters

value

get: Returns {start, end, range}, where range is the preset select's current value, and start/end are each the corresponding picker's value_dictionary (or null) when range is "Custom", and null/null otherwise.
set: Currently broken -- see Known Issues below. Do not rely on this setter.

Observers

None

observed_attributes returns [] -- nothing here is attribute-reactive.

Example


            
        

            let report_range = document.querySelector('#report_range');

            console.log(report_range.value); // {start, end, range} -- reading works today
Known issues (verified against the current source, not fixed here -- documentation-only change):
  • The value setter references this.select_element and this.datetime_range_picker, neither of which this class ever assigns (the real properties set in on_create() are range_select_element and range_picker_element). Calling report_range.value = {range: "Custom"} throws a TypeError rather than applying the change.
  • set_custom_events() builds debounced range_change and range_valid custom-event dispatchers, but neither is ever invoked anywhere in this class -- both are dead code today, and (per the point above) would also throw if they were called. There is currently no way for a consumer to be notified when the range/start/end changes; read value in response to your own listener on the preset select or the nested datetime pickers instead.
