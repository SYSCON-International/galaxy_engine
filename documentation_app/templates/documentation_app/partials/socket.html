Socket

File: GalaxySocket.js
Tag: N/A
Extends: N/A
Owns the lifecycle of a single WebSocket connection. It handles connecting, connection state and automatic reconnection after an unexpected close. Outgoing sends made while a connection is still being established are queued in FIFO order. It also dispatches incoming messages and manages listeners. The class does not know about any protocol. By default it serializes outgoing values to JSON and parses incoming text frames as JSON, but it knows nothing about message types or envelopes: the application registers handlers and interprets the data itself. Every instance is independent, so a page can hold as many sockets as it needs. An application that wants one shared connection keeps a single instance. The class is not created by GalaxyEngine. Import it from GalaxySocket.js.

What the class guarantees:
  • At most one native socket is active at a time. connect() called while already connecting returns the same pending Promise.
  • disconnect() is synchronous and intentional, and it never triggers a reconnect.
  • Events from a replaced (stale) native socket are always ignored.
  • Handlers are called synchronously, in the order they were registered, as each frame arrives. Async handlers are not awaited, so each runs on its own.
  • A handler that throws or rejects is logged with console.error and does not stop the other handlers.

Attributes

None

This is a plain JS class, not a custom element, so it has no attributes. You configure it entirely through the constructor options.

Methods

constructor(options)

  • url (required): a string, or a function that returns one. A function is evaluated again on every connect and reconnect attempt. A relative or http(s) URL is resolved against the current page and given a ws(s) scheme.
  • protocols: sub-protocols passed through to the socket.
  • reconnect (default true): reconnect automatically after an unexpected close. This never happens after disconnect().
  • reconnect_delay: milliseconds, or a function (attempt) => milliseconds where attempt starts at 1. The default is exponential backoff (1s, 2s, 4s and so on) capped at 30s.
  • max_reconnect_attempts (default Infinity): how many failed reconnect attempts in a row are allowed before the socket emits reconnect_failed and becomes disconnected.
  • queue_while_connecting (default true): queue sends made while connecting or reconnecting.
  • max_queue_size (default 100): the largest number of messages the queue holds.
  • serialize: turns a value passed to send() into a frame. By default strings and binary data are sent unchanged and everything else goes through JSON.stringify.
  • deserialize: turns an incoming frame into the value passed to message handlers. By default text frames go through JSON.parse and binary frames pass through. Pass (data) => data to receive raw frames.
  • socket_factory (default (url, protocols) => new WebSocket(url, protocols)): creates the native socket. Use it in tests or to supply another implementation.

connect()

Opens the connection and returns a Promise that resolves once the socket is connected and any queued messages have been sent.
  • While connecting or reconnecting, it opens no second socket and returns the Promise for the attempt already in progress.
  • While connected, it returns a Promise that has already resolved.
The Promise rejects in these cases:
  • disconnect() or destroy() runs before the connection opens.
  • The reconnect attempts run out.
  • Reconnecting is disabled and the attempt fails.

disconnect(code = 1000, reason = "")

Closes the connection on purpose, and does so synchronously:
  • cancels any scheduled reconnect
  • closes the native socket, even one that is still connecting
  • discards queued messages
  • rejects a pending connect() Promise
  • emits close with intentional: true
Any later event from the closed socket is ignored. Calling it while already disconnected does nothing. Calling it from a close handler cancels the reconnect that the unexpected close scheduled.

send(data)

Serializes data right away, so changes the caller makes to the object later have no effect. Returns true if the message was sent or queued, and false if it was rejected. It never throws.
  • Connected: the message is sent immediately.
  • Connecting, reconnecting, or the native socket is already closing: the message is queued and sent in FIFO order once connected, as long as queueing is enabled and the queue has room.
  • Disconnected or destroyed: the message is rejected with a console.warn.
Messages sent from an open handler, such as a set-up message, go out before messages that were queued earlier.

on(type, handler)

Registers a handler and returns a function that removes it. Registering the same function twice for the same event has no effect. Events and the arguments their handlers receive:
  • open: {is_reconnect}
  • message: (data, native_event)
  • close: {code, reason, was_clean, intentional, will_reconnect}. was_clean is null for an intentional close.
  • error: {event} for a native error, {error, raw} for a frame that could not be deserialized, or {error} if the socket could not be created
  • reconnecting: {attempt, delay}
  • reconnect_failed: {attempts}
Handlers belong to the GalaxySocket instance rather than the native socket, so they keep working across reconnects.

off(type, handler)

Removes a handler that was registered with on().

destroy()

Disposes of the socket permanently. It disconnects, cancels timers, discards the queue and removes every handler. After this, connect() rejects and send() and on() do nothing.

Getters / Setters

state

get: One of GalaxySocket.STATES: "disconnected", "connecting", "connected" or "reconnecting".

is_connected

get: True if the connection is open.

queued_count

get: The number of outgoing messages waiting for the connection to open.

Observers

None

This class has no attributes, so there are no attribute observers.

Example


            import { GalaxySocket } from "/static/galaxy_engine/js/GalaxySocket.js";

            let socket = new GalaxySocket({
                // Evaluated on every connect/reconnect attempt, so a dynamic host or port keeps working.
                url: () => `${WEB_SOCKET_URL_PREFIX}://${window.location.hostname}:${SOCKET_PORT}/ws/dashboard_viewer`,
                reconnect_delay: 30000,
            });

            // Per-connection set-up. It runs again after every reconnect, and it goes out before anything queued while connecting.
            socket.on("open", ({is_reconnect}) => {
                if (is_reconnect) {
                    show_success_alert_box("Connection restored.");
                }

                socket.send({message_function: "set_up", user_id: USER_ID});
            });

            // The application does its own routing.
            socket.on("message", async (messages) => {
                for (let message of messages) {
                    await handle_message(message);
                }

                socket.send({message_function: "update_ready_to_accept_data"});
            });

            socket.on("close", ({intentional, will_reconnect}) => {
                if (!intentional && will_reconnect) {
                    show_danger_alert_box("Connection issues. Reconnecting...");
                }
            });

            socket.on("reconnect_failed", () => show_danger_alert_box("Unable to reconnect."));

            await socket.connect();

            // Later: an intentional close never reconnects.
            socket.disconnect(4200);
