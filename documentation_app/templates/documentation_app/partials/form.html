Form

File: GalaxyForm.js
Tag: galaxy-form
Extends: GalaxyHTMLComponentBase

The galaxy-form component is a custom form element that extends the functionality of the base component. It provides a structured way to create forms using the Galaxy framework, allowing developers to easily manage form inputs, validation, and submission.

Note about initialization:
Several steps are taken when a form is initialized:

  1. Set the form's action, method, enctype, novalidate, and target attributes.
  2. Move all direct child nodes of galaxy-form into the form
  3. Run pre_on_create, on_create, and post_on_create for all Galaxy children. This is done after moving the children to prevent the children from running these methods twice. 1st when they are created and 2nd when the form is created and the children are moved to the form. Galaxy children that a child adds while it initializes - a has-confirm galaxy-button's confirmation modal - are initialized too. A Galaxy child is any element extending GalaxyHTMLComponentBase, at any depth, so a new component needs no registration to work inside a form. Children of a nested galaxy-form are left to that form.
Once the form has initialized its children, a Galaxy child connected later (for example one removed and re-added) initializes itself. A field added after initialization still goes through add_field(), which moves it into the internal <form>. Moving the galaxy-form itself keeps its internal <form> and fields.

Attributes

action

Observed: true
Default: ""

The URL to which the form data will be submitted. If not specified, the form will submit to the current page.

method

Observed: true
Default: "GET"

The HTTP method to use when submitting the form. Common values are "GET" and "POST". If not specified, the default is "GET".

enctype

Observed: true
Default: ""

The encoding type for the form data when it is submitted. This is important for file uploads and other types of data. Common values include "application/x-www-form-urlencoded", "multipart/form-data", and "text/plain". If not specified, the default is "application/x-www-form-urlencoded".

novalidate

Observed: true
Default: false

When set to true, the form will not perform any validation on the input fields before submission. This can be useful for forms that require custom validation logic or when you want to handle validation manually. If not specified, the default is false, meaning the form will validate inputs according to HTML5 standards.

target

Observed: true
Default: false

Specifies where to display the response after submitting the form. This can be a named iframe or a window. If not specified, the response will be displayed in the same window.

instant-validation

Observed: false
Default: false

When set to true, the form will validate inputs immediately as the user types or interacts with the form fields. This provides instant feedback to the user about the validity of their input. If not specified, the default is false, meaning validation will occur only when the form is submitted.

submit-on-enter

Observed: false (read when Enter is pressed)
Default: false

Lets Enter in one of the form's single-line Galaxy fields submit it. With a submit button in the form - a native one or a galaxy-button with submit - Enter activates the first one, so a confirmation on it still asks first, and a disabled one blocks Enter. Without one, Enter submits as request_submit(). Either way the form is validated first. Without this attribute, Enter never submits the form, whatever buttons it has. Also honored on a native <form> holding Galaxy fields.

native-submit

Observed: false (read when the form is submitted)
Default: false

Lets a valid form submit natively, posting to its action with its method as a plain form does. Without it, a valid form only dispatches its own submit event for a script to handle. Either way an invalid form is not submitted, and a script can still stop a valid native submission by calling preventDefault() on the form's submit event.

Methods

on_form_submit(event)

Handles the form submission event. It runs when the internal <form> is submitted: by a native submit button placed in the galaxy-form (it is moved into the internal form with the other children), by a galaxy-button with submit (inside the form, or naming it with form="id"), by Enter in a single-line Galaxy field when the form has submit-on-enter (see on_host_keydown()), or by calling request_submit(). A Galaxy field's inner field sits in its own shadow root, outside the internal form, so the browser never submits it on Enter by itself; the field does it. A nested galaxy-form's own submit is left to that form: the outer form neither validates nor submits for it, and does not pass it on as its own. It validates the form: an invalid form is not submitted. A valid one dispatches a cancelable submit event on the galaxy-form; with native-submit the native submission then goes ahead unless that event was cancelled, and without it the native submission is always cancelled.

request_submit()

Submits the form as a submit button would (form_element.requestSubmit()): it is validated, its cancelable submit event is dispatched, and with native-submit it then posts. Use this rather than form_element.submit(), which skips all three.

reset()

Resets the form as a reset button would: every field returns to the value it was created with.

validate(scroll_to_first_invalid = true)

Validates the form inputs according to HTML5 standards or custom validation logic, including the validate() of every Galaxy child that has one. If any input is invalid, it will return false and optionally scroll to the first invalid input if scroll_to_first_invalid is true. If all inputs are valid, it returns true. The first invalid input is whichever comes first of the first Galaxy child whose validate() failed and the first native :invalid element. Before scrolling, reveal_element() opens anything hiding it, such as a closed Collapse. After scrolling, a field made of several fields moves focus to its own first invalid part, if it defines focus_first_invalid() -- as Editable Table does.

reveal_element(element)

Calls reveal() on every ancestor of element that has one, through shadow roots -- e.g. opening every Collapse panel around an invalid field, and selecting the Tab holding it, so it can be seen and scrolled to. Any component that can hide its contents can implement reveal() to take part.

async add_field(element)

Adds a field, or a wrapper containing fields, to the form after it has initialized, and initializes every Galaxy component within it exactly once, with this form as its parent_form. A plain appendChild() into the galaxy-form also works: the form notices the new child and moves it in through this method (see adopt_appended_children()).

get_galaxy_components(root_element)

Returns the Galaxy components (elements extending GalaxyHTMLComponentBase) within and including root_element that belong to this form, skipping any inside a nested galaxy-form. Used to initialize and to validate.

async initialize_galaxy_components(galaxy_components)

Sets this form as each component's parent_form and runs its create lifecycle through initialize_component(), in order. A component that throws is logged and skipped, so its siblings still initialize.
