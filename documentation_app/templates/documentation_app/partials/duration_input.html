Duration Input

File: GalaxyDurationInput.js
Tag: galaxy-duration-input
Extends: GalaxyInputBase
Renders a duration as a row of coordinated integer inputs (a subset of days/hours/minutes/seconds, per visible-units). Editing any field re-derives the combined duration, expressed in output-unit (or unit if not set) -- that output unit stays independent of which fields are shown. If the received value carries more precision than the visible fields can hold (e.g. 90 seconds with only a minutes field), the un-representable remainder is shown as a warning message below the fields rather than silently dropped; the warning is cleared once the user edits any field, since the fields themselves then become the source of truth. Uses Duration Utils for all of its unit math.

Attributes

unit

Observed: true
Default: seconds
The unit the value attribute is expressed in. Falls back to seconds (with a console warning) if set to an unsupported unit.

output-unit

Observed: true
Default: null (falls back to unit)
The unit the value getter returns its composed scalar in. Falls back to unit when not set or unsupported.

visible-units

Observed: true
Default: ["days","hours","minutes","seconds"]
A JSON array naming which day/hour/minute/second fields are rendered, e.g. '["hours","minutes"]'.

hide-labels

Observed: true
Default: false
When present, per-field <label>s are hidden -- fields are separated by label-less-separator and carry aria-label instead.

label-less-separator

Observed: true
Default: ":"
Text shown between fields when hide-labels is set.

unit-labels

Observed: true
Default: DEFAULT_UNIT_LABELS
A JSON object of long-form label text per unit, used as each visible field's <label> and, when labels are hidden, its aria-label.

truncation-warning-template

Observed: true
Default: DEFAULT_TRUNCATION_WARNING_TEMPLATE
Template for the received-value truncation warning message. Its four %s placeholders are filled, in order, with: original value, unit, remainder value, unit.

Methods

async attribute_changed_callback(name, old_value, new_value)

Rebuilds the field row when visible-units, hide-labels, label-less-separator, or unit-labels changes.

async build_fields()

Builds the visible field row (one number input per visible unit, plus a warning paragraph for truncation messages) and inserts it after the label row.

async rebuild_fields()

Tears down and rebuilds the field row in place, preserving the current composed duration, when the visible-field configuration changes after creation.

async build_fields_element()

Builds the field row + warning paragraph as a single container element.

set_field_listeners()

Wires input/blur listeners for each visible field.

remove_field_listeners()

Removes the listeners set up by set_field_listeners().

handle_field_input(unit, event)

Parses and applies one field's raw input text. Empty text is treated as 0; negative numbers, decimals, and non-numeric text are rejected (the field is marked invalid and its last valid value kept) rather than silently coerced. A field exceeding its "natural" range (e.g. minutes: 75 with an hours field present) is not an error -- see handle_field_blur().

handle_field_blur(unit)

Redistributes overflow across the visible fields once the user leaves a field (e.g. minutes: 75 with an hours field becomes hours: 1, minutes: 15), then re-renders all fields with their canonical padded text.

sync_value()

Pushes the current composed value out through Input Base's value-attribute plumbing (hidden input, form value, required-validation) and the State Manager, and fires a native change event on the host. Needed because Input Base's own state-manager write only happens on native input/change events targeting its hidden input -- here the user actually edits the separate day/hour/minute/second fields instead.

render_fields()

Writes the current field values into their inputs. The highest visible unit is shown as a plain integer (it may legitimately grow arbitrarily large); every other field is zero-padded to two digits.

render_warning()

Shows or clears the truncation warning for the originally received value. Cleared once the user has edited any field.

get_validation_errors()

Always returns [] -- this component doesn't itself validate against min/max/required beyond the per-field input rejection described in handle_field_input().

Getters / Setters

value

get: Recombines the current field values into a single scalar, expressed in output-unit (falling back to unit).
set: Replaces the current duration with a new scalar value (expressed in unit), re-decomposes it into the visible fields, and resets the truncation warning and edited state, as if this were a freshly received value.

truncation_info

get: Structured truncation information ({was_truncated, original_value, unit, represented_value, remainder_value}) for the originally received value, so consumers don't need to parse the warning text. Reports was_truncated: false once the user has edited any field.

safe_visible_unit_order

get: visible_units reduced to the canonical days-to-seconds rendering order, falling back to all four units (with a console warning) if the configured list is malformed, rather than letting a bad attribute value throw out of a lifecycle callback.

Observers

None

Handled by a single attribute_changed_callback() rather than per-attribute observer methods.

Example


            
        

            let duration_input = document.querySelector('#cycle_time_input');

            duration_input.addEventListener('change', () => {
                console.log(duration_input.value); // composed value, in `output-unit` (or `unit`)
            });
