Sortable List

File: GalaxySortableList.js
Tag: galaxy-sortable-list
Extends: GalaxyTable
A Table whose rows people put in order themselves -- the tables of a report, the columns of a table. Columns, rows, column render functions, the empty state, and max-body-height work as on the Table. Column sorting (sortable, client-sort) does not, since a manual order and a sort would fight; paging (page-size) does not, since a row has nowhere to move to on another page; and neither does the light-DOM <table> source.

Each row has a drag handle before its cells and up and down buttons after them, each with a tooltip. The handle is dragged with a mouse, pen, or touch: the row follows the pointer and the others shift around it, a scrolling body scrolls when the pointer nears its top or bottom, and Escape puts the row back. The buttons are the fallback where dragging is awkward, and are disabled at the ends of the list. With a handle focused, Alt+ArrowUp and Alt+ArrowDown move its row. Each move is announced to screen readers, and moving a row moves its rendered row rather than re-rendering the list.

It is form-associated: with a name, it submits the items' ids in their order as one JSON array.

Attributes

id-key

Observed: true
Default: "id"
The row field each item is identified by in order, the reorder event, and the submitted value. A row without it is identified by its position in the rows as they were set.

readonly

Observed: true
Default: false
Boolean. Hides the handles and buttons, so the order cannot be changed from the list.

hide-handle / hide-buttons

Observed: true
Default: false
Booleans hiding the drag handles (and with them the keyboard moves) and the up and down buttons. Each takes its column with it.

name

Observed: true
Default: null
The field name the order is submitted under, as one JSON array of ids. Form reset restores the order the rows were last set in from code.

Methods

move_row(from_index, to_index)

Moves a row from one position to another (clamped to the list) and returns whether it moved. Dispatches no event -- events are for user actions.

Getters / Setters

rows

get: Copies of the rows in their current order.
set: Replaces every row (an array or a JSON string), in the order given; that order is the one a form reset restores. Dispatches no event. The list copies the rows, so moves never change the objects passed in. A value that cannot be copied -- a function, a DOM element -- is kept as the same reference (see clone_value()).

order

get: The items' ids in their current order.
set: Puts the rows in the order of the ids given (an array or a JSON string). Rows whose ids are not listed follow, in their relative order. Dispatches no event.

readonly / hide_handle / hide_buttons / id_key / name

get/set: Mirror the matching attributes.

Events

reorder

Bubbling, dispatched when a user's drag, button, or key moves a row to a new position: {order, rows, row_id, row, from_index, to_index}. A drag dispatches it once, on drop, and a drop where the row started dispatches nothing.

Example


            
        

            let list = document.getElementById('report_columns');

            list.columns = [
                {key: "label", label: "Column"},
                {key: "type", label: "Type"},
            ];
            list.rows = [
                {id: "machine", label: "Machine", type: "Text"},
                {id: "parts", label: "Parts", type: "Integer"},
                {id: "rate", label: "Rate", type: "Float"},
            ];

            list.addEventListener('reorder', (event) => console.warn(event.detail.order));
