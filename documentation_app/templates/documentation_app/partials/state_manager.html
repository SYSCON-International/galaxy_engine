State Manager

File: GalaxyStateManager.js
Tag: N/A
Extends: N/A
Two-way binding for application state, available as window.galaxy_state_manager. Every write -- data.property = value from a script, or a Galaxy input reporting a change -- goes through set(), and when the value changed, three kinds of thing are updated:
  • Galaxy inputs with a property-name, which register themselves with bind(). The value is applied through each input's own apply_state_value(), so a checkbox gets a boolean and a select an array. Two inputs sharing a property-name therefore stay in step both ways. An input connecting to a property that already exists adopts its value (state wins); one connecting to a new property seeds it with its own value.
  • Plain elements with data-property, found in the document and in any root added with add_root() (a galaxy-form adds its own). A native checkbox or radio gets .checked, another native field .value (with a change event), and anything else .textContent; null and undefined are written as empty. Values are always written as text, never markup. data-property is not supported on a Galaxy input -- use property-name.
  • Subscribers registered with subscribe().
Arrays and plain objects are compared by content, so re-reporting an equal value is not a change.

Methods

set(property, value, source = null)

Writes a property. If the value changed, applies it to every bound Galaxy input except source, updates every bound plain element, and calls the subscribers. source is the input the change came from, which is not written back to, so an input being typed in keeps its caret. Writing data.property = value calls this with no source. Arrays and plain objects are compared by content, so an equal but freshly built array is not a change; writing back the same array or object is, since that is how a script announces it changed the value in place: data.items.push(item); data.items = data.items;.

bind(property, component) / unbind(property, component)

Registers or unregisters a Galaxy input as bound to a property. Input Base calls these itself when an input with a property-name is created and destroyed; a component bound by hand must define apply_state_value(value). When a bound component throws while taking a value, the error is reported with console.error and the other components bound to the property are still updated.

subscribe(property, callback)

Calls callback(property, value, old_value) whenever property changes, or any property when property is "*". Returns a function that unsubscribes it. A subscriber that throws is logged and does not stop the others.

add_root(root) / remove_root(root)

Adds or removes a root, besides the document, to search for plain data-property elements -- for a component that moves light-DOM content into its own shadow root, where a document query cannot reach it. galaxy-form adds its shadow root.

trigger_dom_update(property, value)

Updates the plain data-property elements bound to a property, following the rules above.

has_property(property)

Whether a property exists in the state.

add_property(property, value)

Adds a property to the state manager with the specified value, defaulting to null.

remove_property(property)

Removes a property from the state manager, as delete data.property does (see delete_property()).

delete_property(property)

Removes a property and clears everything bound to it: bound Galaxy inputs and plain elements are given null (shown empty), and subscribers are called with undefined as the value and the old value. delete data.property and remove_property() both run it. Deleting a property that does not exist does nothing.

update_property(property, value)

Updates an existing property, logging an error instead if the property does not exist or the value is undefined.

update_all_bound_elements()

Re-applies every current state value to the Galaxy inputs and plain elements bound to it.

create_proxy(object)

Creates the data proxy, which routes every write through set() and every delete through delete_property().
